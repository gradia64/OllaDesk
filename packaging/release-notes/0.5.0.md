## What's new

- **Tool access levels (🔧)**: the 🔧 button in the input is now a menu that sets, per conversation, what the model may do with the folders and files attached to it: *Off*, *Read only* (as in 0.4), *Write files* or *Full access*. The wrench turns grey, blue or amber depending on the level. The model only receives the tools of the chosen level, and the phone follows the choice. Conversations saved with the tools on open as *Read only*.
- **Write files**: the model can create text files and folders and change a file, rewriting all of it or replacing an exact piece of text. Every change waits for your confirmation: the bubble shows the diff with *Apply*, *Reject* and *Allow for the rest of the answer*, and the answer stays paused until you choose. Stop or closing the app count as a rejection. The phone shows that a change is waiting, but changes are confirmed only on the PC. Only text files up to 512 KB are written, atomically, with the same exclusions as reading: hidden files, dependencies, `.gitignore`, credentials, links. A file attached on its own can be changed, but nothing can be created next to it.
- **Full access**: the model can also move or rename files and folders and move them to the system trash. Nothing is ever deleted permanently. Moving and deleting always ask, one by one, even after *Allow for the rest of the answer*, and a folder with hidden, excluded or special files or links inside cannot be moved or deleted.
- **Undo the changes**: under an answer that changed files, "↶ Undo the changes" puts them back as they were, also after a restart, and restores files from the trash. It warns if a file changed after the answer. If several answers changed the same files, you undo the most recent first. The "🔧 Tools used" block, on the PC and on the phone, says for each change whether it was rejected or undone, and the model is told when one of its changes was undone.
- **No commands, no git**: the tools work only on what was attached to the conversation. They cannot run commands, and `.git/` is never touched.

## Security

From an external review of this release, before the tag.

- **Faithful confirmation card**: the card shows exactly what you approve. Long lines wrap, and a very long changed line (minified files, JSON) is shortened around the change. Invisible and bidirectional characters, which can make a line read differently from what it does, are shown as `⟦U+202E⟧` with a warning. File names with control or invisible characters are refused. The card also warns when a diff, or the list of a folder to delete, is cut.
- **Changes during the confirmation**: if the file, or a folder on its path, changes while you decide (for example a folder replaced by a link to somewhere else), nothing is written, moved or deleted, and the model is asked to look again. Writes follow the shared folder one name at a time without following links.
- **Undo data**: the undo record is treated as untrusted. A record with unexpected fields is refused as a whole, and undoing only touches paths inside the folders shared by the conversation.
- **App data**: OllaDesk's own configuration folder (conversations, settings, undo copies) stays out of the tools even when a folder containing it, such as `~/.config`, is shared.
- **Stop and closing**: a change applied right before Stop, or before closing the app, is always saved with its "Undo" button. Before, it could stay on disk with no way to undo it.
- **Repeated proposals**: after three rejections on the same file, the model cannot propose more changes to it in the same answer.

## Fixes

- **Line endings**: changing a file with Windows line endings (CRLF) keeps them.
- **File details**: rewriting a file keeps its group, and a read-only file is refused with a clear message.
- **Spanish**: two labels of the "Tools used" block agree with the noun again.

## Technical notes

- **Flatpak**: in the Flatpak, the trash portal of xdg-desktop-portal 1.22 refuses files shared through the document portal, that is, the files attached to the conversation, also when GLib asks. Moving them to the trash fails there with a clear message and nothing is deleted. Writing, moving and undoing work.
- **Undo copies**: copies of the changed files stay in the configuration folder (`undo/`) until you undo the answer or delete the conversation.
- **Rounds**: with a write level the model gets up to 12 rounds of tools per answer instead of 8.
