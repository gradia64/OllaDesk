## Fixes

- **Context window warning**: the warning about a request that is too long now uses the model's real context window. Without a `num_ctx` in Model parameters, OllaDesk used to assume 4096 tokens even when the server uses another default (for example `OLLAMA_CONTEXT_LENGTH=32768`), so it gave false warnings and the wrong advice. Now it reads the window Ollama actually loaded the model with, after each answer, and from Ollama's error when a request is refused. Until it knows the window, the warning says so instead of giving a number as certain. The estimate also counts the tool definitions and the arguments of tool calls, so a request just over the window no longer passes without a warning.
- **The right tip for each error**: every error used to end with "start Ollama with `ollama serve` and check the URL", even when Ollama was running and had refused the request. When a request exceeds the context window, the message now gives both numbers and suggests raising `num_ctx` or reducing attachments and history. The tip about `ollama serve` stays only for connection errors.
- **Empty answers**: when a model finishes without writing anything, a warning explains it instead of leaving an empty bubble. This happens with some models whose template ends the answer at once, or that write nothing with thinking on. There is a different warning when the model only thought and did not write the answer.
- **Attached folders with the tools on**: with 🔧 on and a model that supports tools, an attached folder no longer sends the content of up to 200 files. The model gets the list of readable files and opens the ones it needs with the tools, so a large folder does not fill the context (attaching a whole projects folder went from about 50,000 to about 2,300 tokens). With the tools off, nothing changes.
- **Folder warning**: the summary of what a folder left out reads "reason N" ("hidden 72; unsupported type 149…"), without "1 excluded" or nested parentheses, and "hidden" is now translated.
